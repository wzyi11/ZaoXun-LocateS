## Goal

实现自定义应用背景功能：用户从 Profile 页进入「背景设置」，可选择渐变色预设（6 种）、图片预设（4 张）、或从相册自选图片。选择后所有页面背景立即生效，重启后保持。

## Scope / Non-goals

**Scope**:
- 6 种代码生成的渐变色预设
- 4 张预置图片资源（需用户提供图片文件或 build agent 生成占位图）
- 相册自选图片（通过 `PhotoViewPicker`，无需权限）
- 内容层半透明叠加（白色区域 85% 不透明度）
- 持久化到 Preferences
- 通过 AppStorage 全局响应式同步

**Non-goals**:
- 不改变底部导航栏毛玻璃效果（保持现有 `BlurStyle.Thin`）
- 不变更深色/浅色模式逻辑
- 不涉及服务卡片（WidgetCard）背景

## Current State And Constraints

- **背景现状**: 所有页面根 `Column` 硬编码 `.backgroundColor('#F5F5F5')`，无统一背景机制
- **状态管理**: 项目已使用 `AppStorage` + `@StorageLink` 做全局令牌同步（`itemRefreshToken` 等），本次沿用此模式
- **导航**: 使用 `router.pushUrl` / `router.back()`，从 Profile 页 router 跳转至设置页
- **颜色模式**: `EntryAbility` 中 `setColorMode(COLOR_MODE_NOT_SET)`，跟随系统
- **沉浸式布局**: `mainWindow.setWindowLayoutFullScreen(true)`，各页面手动 `.padding({ top: 36 })`
- **权限**: 当前 `module.json5` 无 `requestPermissions`。`PhotoViewPicker` 无需运行时权限，本次不新增权限声明
- **SDK**: HarmonyOS API 24 (6.1.0.105)

## Design

### 架构总览

```
EntryAbility.onWindowStageCreate()
  └─ BackgroundStore.init(context)   // 从 Preferences 读取并写入 AppStorage
       ├─ bgType  → AppStorage
       └─ bgValue → AppStorage

所有页面 (Index, Profile, ItemDetail, ...)
  build() {
    PageBackground() {              // ← 新增包装层
      // 原有页面内容（去掉 .backgroundColor()）
    }
  }

PageBackground 内部:
  Stack {
    底层: 背景图片 / 渐变色 / 空
    顶层: Column { @BuilderParam content }  // 半透明叠加 #F5F5F5CC
  }

ProfilePage → router.pushUrl → BackgroundSettingsPage
  ├─ 渐变色预设区 (6 种)
  ├─ 图片预设区 (4 张)
  ├─ 自定义相册入口 (PhotoViewPicker → 复制到沙箱)
  └─ 恢复默认按钮
```

### 背景类型枚举 (`BackgroundType`)

| 值 | 含义 | bgValue 存储内容 |
|---|---|---|
| `'none'` | 默认（无背景图） | 空字符串 `''` |
| `'gradient'` | 渐变色预设 | 渐变 ID: `'sunrise'`, `'ocean'`, `'forest'`, `'sakura'`, `'twilight'`, `'aurora'` |
| `'image_preset'` | 预置图片 | 资源名: `'bg_preset_1'`, `'bg_preset_2'`, `'bg_preset_3'`, `'bg_preset_4'` |
| `'custom'` | 自定义相册图片 | 沙箱路径: `'/data/storage/.../bg_custom.jpg'` |

### 持久化方案 — `@kit.ArkData` Preferences

- 文件名: `'app_settings'`
- Key: `'bg_type'` → `string`
- Key: `'bg_value'` → `string`
- 启动时 (`EntryAbility`) 读取 → 写入 `AppStorage`
- 设置页变更时写入 Preferences + AppStorage 同步更新

### 全局背景渲染 — `PageBackground` 组件

`@BuilderParam content` 接收页面内容，包裹在 `Stack` 中：

```
Stack() {
  // 第 1 层：背景
  if (bgType === 'gradient')    → linearGradient 着色 Column
  if (bgType === 'image_preset')→ Image($r('app.media.xxx'))
  if (bgType === 'custom')      → Image(filePath) 从沙箱加载
  // bgType === 'none' → 无背景层

  // 第 2 层：内容（半透明）
  Column() { this.content() }
    .backgroundColor(bgType === 'none' ? '#F5F5F5' : '#F5F5F5CC')
    // #F5F5F5CC = F5F5F5 的 80% 不透明度
}
```

- 渐变色通过 `Column().linearGradient(...)` 渲染，6 个预设写在一个私有函数中通过 `bgValue` 匹配
- 图片预设通过 switch-case 返回对应 `$r('app.media.bg_preset_N')`
- 自定义图片使用 `Image(this.bgValue)` 加载沙箱文件路径，`objectFit: Cover`

### 图片选择方案 — `PhotoViewPicker`

使用 `@kit.CoreFileKit` 的 `picker.PhotoViewPicker`，**无需权限**，选择后复制到应用沙箱：

1. `photoPicker.select(options)` → 获取临时 URI
2. 通过 `fileIo.openSync` 读取临时文件
3. 写入 `${context.filesDir}/bg_custom.jpg`（固定文件名，每次覆盖）
4. 将沙箱路径写入 Preferences

### 渐变色预设 (6 种)

| ID | 名称 | 方向 | 颜色 |
|---|---|---|---|
| `sunrise` | 晨曦暖橙 | TopLeft → BottomRight | `#FF9A9E` → `#FAD0C4` |
| `ocean` | 深海蓝紫 | Top → Bottom | `#4FACFE` → `#00F2FE` |
| `forest` | 森林绿 | TopLeft → BottomRight | `#11998E` → `#38EF7D` |
| `sakura` | 樱花粉 | Top → Bottom | `#F093FB` → `#F5576C` |
| `twilight` | 暮光紫 | TopLeft → BottomRight | `#A18CD1` → `#FBC2EB` |
| `aurora` | 极光绿 | Top → Bottom | `#0BA360` → `#3CBA92` |

### 图片预设 (4 张)

资源文件放入 `entry/src/main/resources/base/media/`:

| 文件名 | 说明 |
|---|---|
| `bg_preset_1.png` | 预设图 1（山峰/自然） |
| `bg_preset_2.png` | 预设图 2（海洋/水纹） |
| `bg_preset_3.png` | 预设图 3（抽象/几何） |
| `bg_preset_4.png` | 预设图 4（简约/纯色纹理） |

> 图片文件需要实际提供。build agent 应生成 4 张纯色 PNG 占位图（各不同颜色），用户后续替换为期望图片。

### 页面改造模式

**改造前**（以 ProfilePage 为例）：
```typescript
build() {
  Column() {
    // ... 页面内容
  }
  .width('100%').height('100%')
  .padding({ top: 36 })
  .backgroundColor('#F5F5F5')  // ← 删除这行
}
```

**改造后**：
```typescript
build() {
  PageBackground() {
    Column() {
      // ... 页面内容不变
    }
    .width('100%').height('100%')
    .padding({ top: 36 })
    // 不设 backgroundColor，由 PageBackground 统一管理
  }
}
```

### 底部导航栏处理

`Index.ets` 的底部栏保持现有配置不变：
```typescript
.backgroundBlurStyle(BlurStyle.Thin, { colorMode: ThemeColorMode.SYSTEM })
.backgroundColor('#E8F0F0F0')
```

背景图会透过 `Stack` 布局显示在底部栏下方，毛玻璃效果使其隐约可见。

## Execution Sequence

### Step 1: 创建数据模型 `model/BackgroundConfig.ets`

- 定义 `BackgroundType` 枚举（或字符串常量联合）
- 定义 `GradientPreset` 接口及其 6 个预设数据数组
- 定义图片预设资源名常量数组
- `EXPORTS: BackgroundConfig.ets → BACKGROUND_TYPES, GRADIENT_PRESETS, IMAGE_PRESETS, GradientPreset`

### Step 2: 创建存储工具 `data/BackgroundStore.ets`

- 导出 `BackgroundStore` 类（或单例）
- `static init(context: common.UIAbilityContext): void` — 从 Preferences 读取 `bg_type`/`bg_value`，写入 AppStorage
- `static async save(type: string, value: string): Promise<void>` — 写入 Preferences + flush + 更新 AppStorage
- `static async reset(): Promise<void>` — 重置为 `'none'` / `''`
- `EXPORTS: BackgroundStore.ets → BackgroundStore`

### Step 3: 添加资源文件

- 在 `string.json` 中添加：`bg_settings_title`（背景设置）、`bg_gradient_section`（渐变色）、`bg_image_section`（预设图片）、`bg_custom_section`（自定义）、`bg_restore_default`（恢复默认）
- 在 `resources/base/media/` 下添加 4 张占位 PNG（各 200×400 纯色图，颜色不同）

### Step 4: 创建 `components/PageBackground.ets`

- 使用 `@StorageLink('bgType')` 和 `@StorageLink('bgValue')` 读取当前背景配置
- 使用 `@BuilderParam content: () => void` 接收子内容
- `build()` 返回 `Stack` 结构：
  - 底层按类型渲染背景（`none` 不渲染，`gradient` 渲染渐变色 Column，`image_preset` 用 switch-case + `$r` 加载，`custom` 用 `Image(filePath)` 加载）
  - 顶层 `Column` 包裹 `content()`，设 `.backgroundColor(bgType === 'none' ? '#F5F5F5' : '#F5F5F5CC')`
- `EXPORTS: PageBackground.ets → PageBackground`

### Step 5: 创建 `pages/BackgroundSettingsPage.ets`

- `@Entry @Component struct BackgroundSettingsPage`
- 顶部导航栏（返回按钮 + "背景设置"标题）
- 内容使用 `List` 组织：
  - **Section: 渐变色预设** — 使用 `Grid`（2 列 3 行）展示 6 个渐变圆角方块，点击选中（高亮边框）
  - **Section: 预设图片** — 使用 `Grid`（2 列 2 行）展示 4 张预设图缩略图，点击选中
  - **Section: 自定义背景** — 按钮"从相册选择"，调用 `PhotoViewPicker`
  - **底部按钮**: "恢复默认"，调用 `BackgroundStore.reset()`
- 选择后立即调用 `BackgroundStore.save(type, value)` 并显示选中状态
- 选中状态通过 `@StorageLink('bgType')` / `@StorageLink('bgValue')` 读取

### Step 6: 注册页面 + 修改 ProfilePage

- 在 `main_pages.json` 数组末尾添加 `"pages/BackgroundSettingsPage"`
- 在 `ProfilePage.ets` 的 `List` 中（"进行中提醒"section 之后，"关于"section 之前）插入新 `ListItem`：
  ```
  Row() { Text('🎨'); Text('背景设置'); Blank(); Text('›') }
    .onClick(() => { router.pushUrl({ url: 'pages/BackgroundSettingsPage' }); })
  ```

### Step 7: 修改 EntryAbility 初始化

- 在 `onWindowStageCreate()` 中，`loadContent` 之前调用 `BackgroundStore.init(this.context)`（同步即可，偏好读取很快）
- 需在文件顶部 `import { BackgroundStore } from '../data/BackgroundStore'`

### Step 8: 修改所有页面使用 PageBackground

针对以下 8 个文件，做统一改造：
1. `Index.ets`
2. `ItemPage.ets`
3. `SpacePage.ets`
4. `EventPage.ets`
5. `ProfilePage.ets`（已在 Step 6 处理）
6. `ItemDetailPage.ets`
7. `AddItemPage.ets`
8. `EventDetailPage.ets`
9. `CreateEventPage.ets`

每个文件改动：
- 添加 `import { PageBackground } from '../components/PageBackground'`
- 在 `build()` 根布局外包裹 `<PageBackground> { ... } </PageBackground>` 尾随闭包语法
- 删除根 `Column` 上的 `.backgroundColor('#F5F5F5')`

> 注意 ArkTS 约束：`@BuilderParam` 尾随闭包传递时，内容必须是单个根组件。所有页面当前已经是单根 `Column`，兼容。

### Step 9: 编译验证

- 运行 `arkts_check` 检查所有 `.ets` 文件
- 运行项目构建验证无编译错误
- 手动验证：进入背景设置 → 选择渐变色 → 返回主页 → 进入物品详情 → 确认背景均显示
- 杀进程重启 → 确认背景保持

## Risks And Compatibility

| 风险 | 影响 | 缓解 |
|---|---|---|
| 图片选择后 URI 过期 | 重启后自定义图片丢失 | 选择后立即 `fileIo` 复制到沙箱 `filesDir`，存储沙箱路径 |
| `$r()` 不能动态拼接 | 图片预设无法用变量名动态加载 | `PageBackground` 中用 switch-case 硬编码每个预设名返回 `$r('app.media.bg_preset_N')` |
| 预设图片文件缺失 | 编译报错 | build agent 先生成占位 PNG（纯色矩形），用户后续替换 |
| `getContext(this)` 在 `@Component` 非入口页面中无法获取 `UIAbilityContext` | 无法初始化 Preferences | `BackgroundStore.init()` 仅在 `EntryAbility` 中调用（该处可拿到 context）。设置页写入通过全局 store 实例（初始化时已持有 context 引用） |
| ArkTS `@BuilderParam` 尾随闭包不支持 | 页面包裹失败 | 已确认 ArkUI 支持 `@BuilderParam` 尾随闭包，语法为 `PageBackground() { ... }` |

## Rollback

如出现问题，回滚步骤：

1. **代码回滚**: `git checkout` — 恢复所有修改文件到改动前状态
2. **配置回滚**: `main_pages.json` 中移除 `BackgroundSettingsPage` 注册项
3. **资源回滚**: 删除 `resources/base/media/` 下新增的 4 张占位图
4. **数据清理**: 如用户已设置背景，Preferences 中残留 `bg_type`/`bg_value` 键不会影响回滚后应用（回滚代码不读取这些键）。如需彻底清理，卸载重装或手动清除 Preferences 文件
