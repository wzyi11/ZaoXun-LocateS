## Goal

修复 Bug：在 `EventDetailPage` 修改物品的 `isPrepared` 进度后，返回 `EventPage` 列表页时进度条不立即刷新。

## Root Cause

```
EventDetailPage.togglePrepared()
  └─ AppStorage.setOrCreate('eventRefreshToken', Date.now())  ← ① 通知 EventPage
  
用户按返回 → Index.onPageShow()
  └─ AppStorage.setOrCreate('eventRefreshToken', Date.now())  ← ② 再次通知
```

两个问题叠加导致刷新失效：

| # | 问题 | 后果 |
|---|------|------|
| A | `Date.now()` 在 ① 和 ② 毫秒级重复时返回相同值 | `@Watch` 不触发（值未变），EventPage 不刷新 |
| B | `togglePrepared()` 是 async，用户可能在其 DB 写入完成后**立即**按返回 | ① 和 ② 几乎同时 → Date.now() 高度重复 → A 问题发生 |

此外，`loadEvents()` 是 async **N+1 查询**（先 getAll events，再逐个 getEventItems），在后台页面运行时有并发覆盖风险。

## Design

### 修复策略

两个独立、互补的改动：

| 改动 | 文件 | 作用 |
|---|---|---|
| `Date.now()` → 递增计数器 | `Index.ets` | **保证 token 值永不重复**，解决 @Watch 静默跳过 |
| 新增 `aboutToDisappear()` | `EventDetailPage.ets` | **离开详情页时兜底触发**，不受 togglePrepared 异步时序影响 |

### 为什么不改 EventPage 或其他文件

- `EventPage` 的 `@StorageLink` + `@Watch` + `loadEvents` 逻辑**本身正确**，问题在于触发源不可靠
- `ItemPage`、`SpacePage` 虽是同样模式，但 ItemDetailPage 没有类似的异步状态修改后需触发的场景
- 修复触发源是最小改动路径

### 技术细节

#### `Index.ets` — 单调递增序号

```typescript
// 新增成员变量
private tabRefreshSeq: number = 0;

// 修改 refreshCurrentTab
refreshCurrentTab(): void {
    this.tabRefreshSeq++;                        // ← 保证每次调用值不同
    const token: number = this.tabRefreshSeq;    // 替代 Date.now()
    if (this.currentTabIndex === 0) {
      AppStorage.setOrCreate('itemRefreshToken', token);
    } else if (this.currentTabIndex === 1) {
      AppStorage.setOrCreate('spaceRefreshToken', token);
    } else if (this.currentTabIndex === 2) {
      AppStorage.setOrCreate('eventRefreshToken', token);
    }
}
```

`tabRefreshSeq` 每次 +1，绝对不会重复。`@Watch` 每次必定触发。

#### `EventDetailPage.ets` — 离开兜底

```typescript
aboutToDisappear(): void {
    AppStorage.setOrCreate('eventRefreshToken', Date.now());
}
```

当用户从 EventDetailPage 返回（router.back）时，`aboutToDisappear()` 在页面销毁前执行。此时：
- `togglePrepared` 的 DB 写入**大概率已完成**（几 ms 的 SQL UPDATE）
- 即使未完成，`aboutToDisappear` 也保证了至少有一次 token 通知，EventPage 会进行刷新

> 保留 `togglePrepared()` 和 `markComplete()` 中已有的 `AppStorage.setOrCreate` 调用不变，作为**页内触发通道**（当用户修改后不立即离开时，EventPage 仍然能收到通知）。

## Risks And Compatibility

| 风险 | 影响 | 缓解 |
|---|---|---|
| `tabRefreshSeq` 溢出 | 长时间运行后数字过大 | JS number 是 64-bit float，整数安全上限 2^53，每日万次操作可用数十亿年 |
| `aboutToDisappear` 在某些路由场景不触发 | 如使用 Navigation 组件替代 router | 该项目仅使用 router，兼容 |
| 对 ItemPage/SpacePage 的副作用 | token 不再基于时间戳 | token 语义仅为"是否变化"，不影响正确性 |
